# supplier-source-racing

## 目标
把“搜货源”从一次性最低价搜索，升级为可复用的稳定供应商赛马流程。适用于订阅、数字权益、API、SaaS、卡密、代充等高波动货源。

## 核心原则
1. **先统一商品规格，再比较价格。** 不同交付方式、地区、周期、账号类型、质保条件不得直接混排。
2. **价格第一，但最低价不自动获胜。** 异常低价、成品号、共享号、短质保、不可持续渠道必须单独降权或剔除。
3. **稳定性必须有公开证据或实测证据。** 关注持续运营时间、库存连续性、价格波动、质保、售后和多平台存在。
4. **平台只是证据源，不是供应商本身。** 16688、链动、独立站、PriceAI、Airadar 等要区分“交易平台 / 分销平台 / 雷达聚合”。
5. **识别同源货。** 同标题、同价格、同库存变化、同兑换页、同售后措辞可能是同一父货源的多层转售，不能当成多个独立备份。
6. **最终只给决策结果。** 默认每个 SKU 最多输出 Top 3；优先形成“1 主供 + 1 备供 + 1 观察”。
7. **两轮内必须收口。** 第一轮完成广泛发现与稳定性初筛；第二轮只验证 Top 候选的购买入口、真实结算价、发货/充值机制、质保与可接入性。第二轮结束必须给出“可直接接入 / 可直接采购 / 暂不接入”的明确结论，禁止无限研究。
8. **发货方式必须单列且写死。** 不允许用“在售”“可用”“秒冲”代替交付机制。必须区分“自动发CDK”“CDK自助充值”“全自动充值”“人工充值”“人工审核后充值”“API自动”“发货方式未确认”。如果证据只证明 CDK，不得自行推断自动发货。

## 固定执行流程
### A. 定义可比 SKU
为目标商品建立统一条件：
- 产品/档位
- 周期
- 自有账号充值 / 成品号 / 共享号
- 地区
- 交付方式：CDK / Session 直充 / API 直充 / 人工代充
- 发货/充值自动化：自动发CDK / CDK自助充值 / 全自动充值 / 人工充值 / API自动 / UNKNOWN
- 是否可覆盖
- 是否支持续费
- 质保规则

规格不一致时必须拆榜。

### B. 多源发现
按以下层级搜索：
1. 交易/货源平台：16688 等
2. 分销平台：链动小铺等
3. 独立站
4. 聚合雷达：PriceAI、Airadar 等
5. 商家自己的公开社媒/公告/商品页

### C. 事实采集
内部至少记录：
- 当前价格
- 7/30 天历史价格（可得时）
- 当前库存与缺货状态
- 公开运营时间/收录时间
- 质保天数与退款/掉订规则
- 交付方式/地区/覆盖条件
- **发货方式：自动还是人工，自动到哪一步**
- **客户是否需要自己去兑换页提交**
- **是否能由我们的后台直接完成，不暴露上游给客户**
- 是否多平台出现
- 是否可批发/招代理/API
- 价格和库存证据时间
- 实测订单结果（如有）

### D. 异常过滤
默认排除或单独标记：
- 成品号冒充正规直充
- 共享/拼车
- 只保首登、数小时质保
- 商品规格不明
- 异常低于同类市场且无法解释
- 新店、低库存且无售后证据
- 同一父货源的重复马甲店

### E. 评分
默认权重：
- 价格：45%
- 稳定性：35%
- 售后：15%
- 供应深度：5%

稳定性包括：运营连续性、库存连续性、价格波动、商品持续存在、多平台交叉验证。

### F. 两轮收口规则
**第一轮：发现与初筛**
- 广泛搜索同规格货源
- 剔除成品号、共享、短质保、规格不清
- 每个 SKU 压缩到最多 3 家
- 必须标出当前价格、库存/运营证据、发货方式（已确认或 UNKNOWN）

**第二轮：可接入验证**
只研究第一轮 Top 候选：
- 原始购买入口是否可直接下单
- 实际结算价是否与聚合价一致
- 自动发货还是手动发货
- 如果是 CDK：是否付款即自动出码，是否需要自助兑换，兑换页是谁
- 如果是代充：是否人工处理、处理时段、平均到账时长
- 如果是 API：是否有正式商户 API、余额、创建订单、查询订单
- 质保、失败退款、掉订规则
- 是否适合我们当前“客户只接触 dkai.store、后台人工履约”的流程

第二轮结束必须输出：
- `READY_NOW`：现在即可直接采购/接入
- `READY_MANUAL`：可用于当前人工履约，但没有 API 自动化
- `READY_API`：具备正式 API，可进入自动化接入
- `HOLD`：信息或稳定性不足，继续观察
- `DROP`：淘汰

### G. 最终输出
不要输出研究过程、长供应商清单或内部字段。
**供应商 TOP 必须放在回答最开头。**
每个 SKU 最多输出 3 家，固定增加“发货方式”列：

| 排名 | 供应商 | 当前成本 | 发货方式 | 标签 | 结论 |
|---:|---|---:|---|---|---|
| 1 | A | ¥x | 自动发CDK / CDK自助 / 人工充值 / API自动 | `价格稳` `长期运营` `库存稳` `质保` | 主供候选 |
| 2 | B | ¥x | … | `更便宜` `待实测` | 备供候选 |
| 3 | C | ¥x | … | `特殊能力` | 观察 |

必须补一句：
- 当前建议主供是谁
- **它到底是自动发货还是手动发货，自动到哪一步**
- 为什么不是绝对最低价那家
- 当前是否已经达到 `READY_NOW / READY_MANUAL / READY_API`

## 订阅类专项规则
对 Plus / Pro / Claude 等订阅：
- “自己的账号正规充值”与“成品号”绝不混榜
- “正式订阅 30 天质保”优先于“首登质保”
- iOS / Google / 官网卡付 / 菲区等必须标渠道
- 可覆盖与不可覆盖分开理解
- 若官方规则变化导致某档无法新开，应从主供榜移出而不是继续按旧价赛马
- **“CDK”只表示交付介质，不等于自动充值。** 必须进一步确认是“自动发CDK后客户/我们自助兑换”，还是“提交CDK后上游人工处理”。
- **“秒冲”也不等于 API。** 没有正式商户 API 证据时不得标 `API自动`。

## 证据纪律
- 聚合站仅用于发现和交叉验证，结算价格以原店为准
- 不能把“收录时间”直接等同于真实经营年限，只能作为公开运营证据
- 库存数字可能是商家挂牌库存，不等同于真实可履约数量
- 未实测不得写“已验证稳定”
- 无法确认的事实必须标 UNKNOWN，不补猜
